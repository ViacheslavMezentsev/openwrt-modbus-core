# Страница schoolbell на роутере

[English](README.en.md)

Рабочая страница LuCI: `http://<router>/cgi-bin/luci/admin/schoolbell`.
Используйте фактически настроенный HTTP/HTTPS и обычный вход LuCI.
Это ручной тест короткого поставленного `test.mp3`, не планировщик звонков.

- **Послушать здесь** — браузер получает MP3, звук из телефона/планшета/ПК.
- **Позвонить на роутере** — защищённый POST запускает один фиксированный файл
  через `madplay --no-tty-control -a 0 -R 48000 -o /dev/dsp`.
- Системная/тёмная/светлая тема переключаются одной кнопкой.
- Никаких автозапусков или изменения микшера. Exit 0 не гарантирует слышимость.

## Установка и откат

Это отдельный инженерный payload, ещё не автономный IPK. Зависимости:
Lua 5.1, LuCI с nixio и luci.jsonc, madplay и работающее USB-аудиоустройство.
Установка не включает зависимости и не меняет конфигурацию uhttpd.

Перед установкой сохраните существующие файлы по путям `root/` вместе
с правами и хешами; отсутствующие отметьте отдельно. Проверьте место на overlay.
Скопируйте содержимое `root/` в корень роутера, сохранив каталоги 0755 и файлы
0644. Из `../media/test.mp3` установите файл
`/usr/share/schoolbell-sound-test/test.mp3` (0644). Контрольный SHA256:
`1ae57af4d27698b0cd3795de7287c0dd1b5e2b336e8d9e8dcc9b853cbd8b4e0d`.
Сбросьте только генерируемый `/tmp/luci-indexcache`, не перезапуская службы.

Для отката сначала убедитесь, что тест завершён и файлы не изменены после
установки. Восстановите сохранённые файлы с метаданными, удалите только
добавленные этим payload файлы и снова сбросьте индекс LuCI.
Не удаляйте общие каталоги `luci`, `www`, пользовательские настройки или мелодии.

## Границы и проверка

`sound_test.lua` — диагностический путь, отдельно от production-контракта
native player, медиатеки и очереди. Браузер не задаёт argv/путь/громкость.
LuCI требует вход и POST-токен. Опрос ребёнка: 100 × 100 мс, затем SIGKILL
собственному незавершённому ребёнку и 20 × 100 мс для подтверждения завершения.
Это бюджет вызовов, не гарантия времени Linux.

`/tmp/schoolbell-sound-test.lock` координирует только эту страницу. При
неизвестном исходе он остаётся: проверьте живые процессы по SSH, прежде чем
снимать блокировку. Не запускайте другие проигрыватели одновременно.
Закрытие вкладки не означает STOP; короткая мелодия может доиграть.
Автоматического восстановления worker после сбоя здесь нет.

Хост: `lua5.1 packages/schoolbell/tests/test_sound_test.lua`, входит в
`make ci-schoolbell`. Проверены на MR3020 обычный вход, оба маршрута (пользователь),
anonymous 403 для страницы/sample/play, native fixture и реальный madplay exit 0.
Авторизованный отрицательный CSRF-сценарий проверен на хосте и инспекцией LuCI;
отдельного HTTP-теста с неверным токеном авторизованной сессии не было.
Дополнительный overlay в конкретном опыте около 20 КиБ; это не универсальная квота.
Ядро/demo, сеть и USB-конфигурация сохранены. Reboot и питание не тестировались.


## Полный комплект редактора

На этой же странице теперь редактируются постоянные **неактивные** черновики.
[Формат, API, лимиты и восстановление](../../../docs/packages/schoolbell/SCHEDULE_EDITOR.md).
Из корня репозитория:

```sh
python3 packages/schoolbell/router-page/build-payload.py /tmp/schoolbell-page.tar
```

Комплект содержит страницу/звук и приватные зависимости календаря/JSON/хранилища
в /usr/share/schoolbell-editor; модули установленного ядра не заменяются.
Перед распаковкой на роутере сохраните все целевые пути tar с метаданными.
Создайте /etc/schoolbell-editor с правами 0700 только при отсутствии;
при обновлении никогда не очищайте черновики. После замены контроллера сбросьте
luci-indexcache и скомпилированный module cache luci.controller.schoolbell_test.
Предыдущая инструкция копирования только root относится к звуковому поднабору;
для редактора используйте полный комплект. Откат восстанавливает код и сохраняет
черновики /etc/schoolbell-editor; восстановление пользовательских данных — отдельная операция.
