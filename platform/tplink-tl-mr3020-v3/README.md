# MR3020 v3: оформление консоли и переключатель

[English](README.en.md) · [Документация](../../docs/README.md)

Пользовательские исходники сохранены по поручению владельца с TL-MR3020 v3.30,
OpenWrt 19.07.9. Это часть разработки поддержки платформы, а не дамп роутера
и не готовый устанавливаемый пакет. Содержимое выбранных файлов сохранено
без изменений; контрольные суммы сверены при read-only извлечении.

## Состав

| Исходник | Путь на роутере и назначение |
| --- | --- |
| [MOTD](files/etc/profile.d/00-custom-motd.sh) | `/etc/profile.d/00-custom-motd.sh`: цветной ASCII-баннер MR3020 v3, версия, kernel, uptime/load, память, диск, IP, USB/ACM/видео/аудио и положение переключателя |
| [AP](files/etc/rc.button/mode-ap) | `/etc/rc.button/mode-ap`: на `ACTION=pressed` записывает `ap` |
| [3G](files/etc/rc.button/mode-3g) | `/etc/rc.button/mode-3g`: на `ACTION=pressed` записывает `3g` |
| [WISP](files/etc/rc.button/mode-wisp) | `/etc/rc.button/mode-wisp`: на `ACTION=pressed` записывает `wisp` |
| [Отладка](files/etc/hotplug.d/button/00-debug) | `/etc/hotplug.d/button/00-debug`: отправляет BUTTON/ACTION/SEEN в системный журнал |

Три обработчика только пишут `/tmp/switch_position`; они не переключают сеть.
MOTD читает этот файл, при отсутствии показывает `unknown`. Значение временное:
эти файлы сами не определяют начальное положение при загрузке. Их наличие
не доказывает, что все три положения проверены или события доставляются после
смены версии OpenWrt. Отладочный hook сохранён как наработка, не как обязательный
компонент будущего пакета.

На исходном устройстве `/etc/banner` содержит лишь перевод строки. `/etc/profile`
печатает его и подключает `profile.d`; строка PS1 обычная. Поэтому красивое
«приглашение» здесь именно MOTD, а не отдельная реализация командной оболочки.
Не копируем системный profile и не затираем banner при будущей установке автоматически.

## Связь со сторонним slide-switch

На стенде установлен `slide-switch` 0.9.5-1: CLI `/usr/sbin/slide-switch`,
библиотека/данные в `/usr/share/slide-switch/`, `50-slide-switch` в hotplug.d/button
и init-служба `zzz-slide-switch`. В заголовках указан проект
[openwrt-slide-switch](https://github.com/jefferyto/openwrt-slide-switch), GPLv2.
Сторонний код не включён в этот каталог; пользовательские mode-handlers не являются
его полной заменой. Вызовы init/update/switch не выполнялись при сохранении.
Совместную обработку событий/владение файлами нужно проверить до упаковки.

## Известные ограничения сохранённого оформления

- `OpenWrt 19.07.9` жёстко указана в тексте: при переносе версия будет неверной.
- Нет проверки модели и отдельного guard интерактивного терминала; файл
  подключается окружением profile. Цветной вывод нельзя считать пригодным для
  всех способов SSH/автоматизации без проверки.
- Память вычисляется как Total−Free, не по Available, то есть включает cache.
- Диск показан по `/`, а не отдельным измерением доступного overlay.
- USB подсчитывается через `lsusb`; без этой утилиты вывод может выглядеть как 0.
- Число PCM/video/tty узлов не равно числу физических устройств.
- IP ищется в `br-lan`, затем `eth0`; произвольные сетевые конфигурации не поддержаны.
- Source-файлы здесь имеют mode 0644, намеренно не установочные права:
  будущий пакет должен назначить rc.button 0755, profile/hotplug — по механизму запуска.

## Возможный отдельный пакет

Рабочее имя предложения: `mr3020-console`, отдельно от ядра и прикладных пакетов.
До реализации согласовать собственный контракт/документацию пакета: board/version
проверка, независимость MOTD и switch-handlers, интерактивность, зависимости,
сохранение пользовательских изменений, конфликты с opkg-владельцами, install/remove
и откат. Для switch — startup state и поведение с существующим slide-switch.
Установка не должна подменять сетевые режимы или автоматически менять GPIO.

Сейчас нет Makefile-цели, IPK, install-hook или автоустановки этих файлов.
Синтаксис проверяется `sh -n` без исполнения; сравнение копий не заменяет тесты
загрузки, входа в shell и физических положений переключателя. На роутере ничего
не изменялось. До будущей установки подготовить отдельный проверяемый backup/rollback.
