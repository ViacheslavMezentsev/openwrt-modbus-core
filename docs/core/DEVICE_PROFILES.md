# Загрузчик профилей устройств и лимиты

[English](DEVICE_PROFILES.en.md) · [Карта чтений](READ_GROUPING.md)

Принятый контракт, core 6.9 (р.1.23). Реализация только на хосте:
[device_profiles.py](../../scripts/device_profiles.py),
[profile_limits.py](../../scripts/profile_limits.py),
[21 тест](../../scripts/test_device_profiles.py).
`python3 scripts/test_device_profiles.py` включён в make all/ci-core.
Ничего не устанавливается; modbusd, IPK, UCI и роутер не изменяются.

## Файл и доверие

Целевой каталог установленной системы: `/usr/share/modbus-rtu-core/profiles/`.
Профили поставляются доверенными пакетами. ID имеет вид
`[a-z0-9][a-z0-9_-]{0,31}` и совпадает с именем `<id>.json` и ссылкой map у устройства.
Адрес порта, unit и расписание принадлежат экземпляру устройства, не профилю.
Версия поставки принадлежит пакету; дополнительных версий в JSON пока нет.

```json
{
  "id": "example-sensor",
  "read_ranges": [
    {
      "function": 3,
      "start": 100,
      "count": 20,
      "safe_read": true,
      "mergeable": true,
      "max_count": 20,
      "max_gap": 0
    }
  ]
}
```

Обязательны id/read_ranges и function/start/count диапазона; остальные поля имеют
принятые defaults карты. Неизвестные поля, дубли ключей на любом уровне, NaN/Infinity,
неверный UTF-8, дроби/bool вместо целого, неверные типы, пустая карта и пересечения
отклоняются. Корень — объект, read_ranges — массив объектов. Структура требует
максимум три уровня вложенности; загрузчик проверяет это до JSON decode.
Байтовый лимит проверяется до разбора, с ограниченным чтением limit+1.
Профиль — только данные, без исполнения Lua, загрузки зависимостей или сетевых запросов.

На хосте вызывающий передаёт **доверенный корневой каталог стенда** и bindings
`{device_id: profile_id}`. Загрузчик открывает его один раз и читает только
канонические выбранные файлы относительно directory fd. Symlink и нерегулярные
файлы отклоняются; FIFO не блокирует процесс. Один ID имеет одно каноническое имя:
нет поиска по путям и приоритета перекрывающих файлов. Конфликт владения этим файлом
между пакетами должен отклоняться установщиком, а не решаться перезаписью.
Права/владелец каталога предполагаются доверенными в модели; production-проверка
поставщика/владения файлами остаётся частью установки. Парсер не доказывает safety карты.

## Активация

`ProfileStore.activate(directory, bindings, maintenance=True, active_operations=0)`:
проверить все bindings → загрузить уникальные выбранные профили → проверить общие
лимиты → опубликовать неизменяемые profiles/bindings/maps. Одинаковая карта используется
несколькими устройствами без повторного разбора. Невыбранные файлы не загружаются.

Любая ошибка сохраняет все прежние объекты конфигурации; при холодном старте остаётся
пустая конфигурация и ошибка вызывающему. Ошибка не включает fallback на старый путь.
Maintenance и отсутствие операций обязательны; в модели это проверяемые входные
утверждения вызывающего, не настоящий механизм остановки modbusd. Подключённый
Scheduler получает проверенную копию bindings и ссылки на неизменяемые карты;
автоматической горячей подмены в уже работающем scheduler нет.

## Принятые пределы

| Объект | Лимит |
| --- | --- |
| JSON-файл | 16384 байта до decode |
| Диапазоны одного профиля | 64 |
| Уникальные используемые профили | 16 |
| Сумма диапазонов выбранных профилей | 256, общие копии не считаются повторно |
| Логические устройства | 32 |
| Полезные данные логического чтения | 1024 байта: до 512 слов или 8192 бит |
| Фрагменты логического чтения | 16, дополнительно к ограничению байтов |
| Потребители одной группы | 16; остальные остаются в FIFO |
| Суммарный резерв сборок | 8192 байта полезных данных |

До enqueue проверяются размер результата и `ceil(count / max_count)` фрагментов.
Превышение — отказ без усечения и изменения очереди. Максимум 512 слов не разрешает
512 фрагментов по одному слову: оба ограничения действуют одновременно.
Ожидающие запросы содержат только описание. Перед запуском резервируется вся сборка;
при нехватке места запрос остаётся в очереди с исходным дедлайном. Порт не входит
в RTU-раунд до получения резерва. Ожидание памяти не блокирует соседей или IPC.
Резерв сохраняется между фрагментами и освобождается при любом терминальном исходе,
включая отмену, timeout и истечение срока между фрагментами.

В модели общий пул принадлежит scheduler; тест может передать уменьшенный/общий пул
для воспроизведения дефицита. При текущих семи транспортах и одном active на каждом
сумма семи сборок по 1024 байта составляет 7168 байт: обычный предел 8192 имеет запас.
Тест насыщения общего пула не выдаётся за наблюдение нехватки RAM на роутере.

WireSequence хранит параметры и формирует следующий запрос по индексу, без списка
всех фрагментов. Assembly использует упакованный bytearray, включая биты; отдельной
таблицы всех битов больше нет. Результаты потребителей формируются последовательно,
но Pass.results модели удерживает их до передачи вызывающему. Эти копии, входной
JSON, объекты Python/Lua, RX/TX, кэш и IPC **не входят** в 8192 байта резерва.
Это лимит полезных данных, не общий RAM cap и не измерение MR3020.

## Граница следующего этапа

[Строгий Lua-декодер](STRICT_JSON.md) включён в пакет; старый decode сохраняет
необязательный luci.jsonc. До production нужны Lua loader с depth=3 и схемой, права каталога,
профили реального оборудования и измерение пиков памяти при decode/fan-out/IPC.
Хостовый loader работает в WSL/Linux; его POSIX directory-fd API не переносится
автоматически в Lua или нативный Windows Python.
