# Адресация, шлюзы и настройки расширений

[English](GATEWAY_ARCHITECTURE.en.md) · [ТЗ ядра](TECHNICAL_SPECIFICATION.md)

## Принятая архитектура, реализация впереди

Логическое устройство имеет постоянное имя независимо от IP, tty и unit.
Пример маршрутов одной TCP-точки gateway_a:

| Устройство ядра | Внешний адрес | Назначение шлюза |
| --- | --- | --- |
| room1_sensor | gateway_a / unit 11 | rs485_1 / unit 1 |
| room2_sensor | gateway_a / unit 12 | rs485_2 / unit 1 |

Одинаковые slave ID допустимы на разных линиях. Два одинаковых ID на общей
линии не становятся различимыми благодаря таблице маршрутов. Неизвестный
маршрут не вызывает рассылку запросов. Точные UCI/API-схемы ещё не выбраны.

Прямой режим: ядро управляет портами (в том числе Serial Monster) раундами.
Автономный шлюз: плата обслуживает линии и маршруты независимо от роутера;
общий барьер ей не навязывается. Очередь каждой RS-485-линии общая для входных
клиентов, с одним владельцем передачи и одной активной RTU-транзакцией.

Роли: disabled; modbus-client (запросы к нижестоящим устройствам);
modbus-server (входные запросы); monitor (только приём); bridge (пересылка);
debug (диагностика). Monitor/bridge — отдельные будущие этапы. Роли проверяются
на конфликты; фильтры задают unit/функции/регистры/записи/частоту.

Modbus TCP — клиентский транспорт ядра, RNDIS — способ сетевого подключения.
Первый профиль: одна незавершённая операция на TCP-соединение. Сервер Modbus TCP
на роутере и произвольный прокси не включены автоматически. ТЗ шлюза и контракт
его управления оформляются отдельно до реализации прошивки.

Стандартный автономный комплект должен включать kmod-mii, kmod-usb-net,
kmod-usb-net-cdc-ether, kmod-usb-net-rndis и отсутствующие зависимости для точного
ABI/платформы. Это отдельные IPK, не .ko в универсальном Lua-пакете. Нужны
проверки целостности, доверия, места и автономного reboot. Установка не меняет
LAN/IP/DNS/маршрут/firewall. Текущий make build этот комплект ещё не собирает.

## Принятые требования к пользовательским настройкам

Принято разделение: требуется различать настройки, пользовательские данные и временное состояние:

| Содержимое | Целевое размещение | Владелец |
| --- | --- | --- |
| Настройки/планы | `/etc/<package-id>/settings.json` | Пакет |
| Пользовательские мелодии/данные | Явно выбранный постоянный каталог; например `/srv/<package-id>/` | Пакет и профиль хранения |
| Кэш, PID, текущая очередь | `/tmp/<package-id>/` | Runtime пакета |
| Заводские ресурсы | `/usr/share/<package-id>/` | Поставка пакета |

Архитектура принята в ТЗ 1.16, раздел 6.6; реализация отсутствует. На OpenWrt /var обычно
не подходит для постоянных данных; /srv без внешнего носителя расходует overlay.
Профиль обязан проверить реальную ФС/место. Частые изменения телеметрии и очередей
не записываются во Flash. Путь назначения не берётся из загруженного JSON.

Пакет владеет схемой, миграциями и активацией. Core 1.17 отделяет чистый
settings.json от package.json/settings.schema.json и служебных метаданных.
[Формат и API](EXTENSION_FORMAT.md). Lua 5.1 не содержит JSON из коробки;
зависимость от парсера явная.

Импорт: разобрать без выполнения кода → проверить контекст/метаданные/лимиты → вызвать
валидацию и миграцию пакета → показать изменения → сохранить/активировать по
контракту пакета. Ошибочный импорт сохраняет действующую конфигурацию. Rename
одного файла сам по себе не гарантирует устойчивость при потере питания и
атомарность комплекта из нескольких файлов: требуется отдельное решение по
сбою записи, fsync, откату и активации. conffiles также не заменяет backup.

Два разных внешних формата использования:
- шаблон партии: общие планы и настройки без сетевых адресов, идентификаторов
  оборудования и секретов; привязки к местным логическим устройствам проверяются;
- backup конкретного устройства: версии, конфигурация и manifest пользовательских
  файлов; правила включения секретов задаются явно, не наследуются от шаблона.

Мелодии не встраиваются в обычный JSON настроек: ссылки на media ID/revision
проверяются пакетом; перенос самих файлов требует отдельного ограниченного
архива и проверки места/целостности. Массовый импорт не должен незаметно запускать
звук или менять сеть: сначала проверка/подготовка, затем явная активация.

Плановые критерии TC-93–100: round-trip экспорт/импорт; чужой пакет/версия;
повреждённый/слишком большой JSON; отсутствующая мелодия; несовместимая миграция;
ENOSPC/сбой питания; тиражирование на два устройства без копирования их уникальных
привязок. Schoolbell уже имеет собственные требования backup/restore; общий helper
может помочь выполнить их, но не заменяет их и не добавлен этим этапом.
