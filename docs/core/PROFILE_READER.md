# Системное чтение профилей

[English](PROFILE_READER.en.md) · [Загрузчик](DEVICE_PROFILES.md)

profile_reader.lua входит в IPK; modbusd его не вызывает. Используется уже
объявленный luci-lib-nixio, новых зависимостей нет.

## API и доверие

reader.system() возвращает callback для device_profiles.new либо nil, {code=...}.
Фиксированный каталог: /usr/share/modbus-rtu-core/profiles.
Callback принимает канонический ID и строго 16385 (16384+1), возвращает строку
либо nil, {code=...}. Исключения I/O перехватываются; loader сообщает код read.

reader.new(nixio_backend, absolute_root) — интерфейс тестов/доверенного ядра,
не путь от клиента. Максимум 256 байт/16 компонентов; без пустых компонентов,
точек, NUL и завершающего /. Нет shell, io.open или ослабляющего защиту fallback.

Вся цепочка от / и файл принадлежат UID 0, без записи для группы/остальных.
Профиль — обычный файл, одна жёсткая ссылка, максимум 16384 байта.
Симлинки запрещены. Root-owned /tmp с режимом 1777 тоже отвергается.
Unix-владение не доказывает подпись поставщика или отсутствие конфликта opkg.

## Алгоритм

Открыть / и удерживать дескрипторы родителей; каждый компонент открывать через
/proc/self/fd/N/name с O_DIRECTORY, O_NOFOLLOW, O_CLOEXEC и O_NONBLOCK.
Системная ссылка procfs намеренная; компоненты каталога — no-follow.
Сравнить lstat до открытия с fstat дескриптора: тип, UID, права, dev/ino/nlink.

Читать блоками до 2048 байт, максимум limit+1; больше 16384 — отказ.
Короткое чтение продолжается; ошибка чтения завершает операцию.
FIFO отвергается до open; NONBLOCK защищает при его подстановке в гонке.
После чтения повторно проверить дескрипторы/имена через удерживаемых родителей,
а у файла также size/mtime/ctime и фактическое число прочитанных байт.

Все дескрипторы закрываются в обратном порядке при любом исходе. Ошибка close
отменяет успех; остальные закрываются, повторный close не выполняется.
Максимум 18 FD при 16 компонентах тестового пути; штатно 6.

## Платформа и ограничения

API проверен по [исходникам nixio 19.07](https://github.com/openwrt/luci/tree/f25285a6c26e8776f153994704710cb8e51fad91/libs/luci-lib-nixio/src).
Именованных nofollow/directory/cloexec нет; используются Linux UAPI числа
131072/65536/524288. NONBLOCK берётся из nixio.
Источники: [asm-generic](https://github.com/torvalds/linux/blob/v4.14/include/uapi/asm-generic/fcntl.h),
[MIPS](https://github.com/torvalds/linux/blob/v4.14/arch/mips/include/uapi/asm/fcntl.h).
Допускаются Linux mips/mipsel и тестовый x86_64; иначе отказ.
Отсутствие nixio/procfs — отказ. Изолированная проверка OpenWrt/MIPS принята; условия приведены ниже.

Установщик не должен параллельно менять каталог/файлы во время активации.
Метаданные обнаруживают проверяемые подмены, но не дают защиты от root,
изменения на месте с теми же метаданными или смешения поколений нескольких файлов.
Timestamp nixio имеет секундную точность. Mount namespace/procfs доверены.
NONBLOCK не ограничивает время дискового I/O. Общие RAM/latency не измерены.
Происхождение пакета и координация установщика остаются отдельными задачами.

## Проверки

make all/ci-core: 13 групп test_profile_reader.lua — параметры, права/типы/ссылки,
open/stat/read/close, подмены/рост/лимиты, сохранение активной конфигурации.

Отдельно test_profile_reader_native.py с настоящим nixio на Linux-хосте от root:
реальные файлы/права/FIFO/ссылки/размер, три подмены у open/read, стабильное число FD
после 200 чтений. Временный стенд создаётся и удаляется под /root, не на роутере.

Для повторения собрать host Lua 5.1/nixio указанной ревизии, задать LUA_BIN,
LUA_PATH, LUA_CPATH и при необходимости LD_LIBRARY_PATH, затем из репозитория
выполнить python3 scripts/test_profile_reader_native.py от root хоста.
Native-тест не входит в make all; mock-PASS его не заменяет.

## Принятая проверка на целевой системе — 15.10.2026

Проверен код c68dec5 на MR3020 v3.30, OpenWrt 19.07.9, kernel 4.14.267,
Lua 5.1, machine=mips; luci-lib-nixio git-22.045.73925-36e5c1c-1.
Изолированные копии модулей/тестов сверены по SHA256; установленное ядро не обновлялось.

PASS: 20 групп strict JSON, 19 schema/activation, 13 reader fault-групп.
На реальной файловой системе прошли проверки прав/UID, размеров, FIFO, симлинков
и жёстких ссылок; три подмены у open/read отвергнуты. После 200 чтений число FD
не выросло. Реальный reader -> loader активировал профиль и сохранил прежний снимок
после ошибки следующего чтения. Фабрика system() успешно создавалась.

Положительные чтения использовали отдельный доверенный временный каталог под /root.
Штатный каталог профилей не создавался и через system() не читался.
30 контрольных хешей установленных файлов/настроек и PID/starttime core/demo
сохранились. Core online/valid, данные BluePill/demo оставались свежими.
Стенд удалён; serial не открывался, modbusd не подключался и не перезапускался.

Это принятое свидетельство изолированного опыта, не новая гарантия платформ.
Не проверены интеграция транспорта, исключение параллельной установки,
происхождение пакетов, длительная работа и общие RAM/CPU/latency.
Исходные аппаратные журналы и стенд остаются вне Git.
