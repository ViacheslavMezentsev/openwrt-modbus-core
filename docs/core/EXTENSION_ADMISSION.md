# Минимальный manifest и допуск расширения

[English](EXTENSION_ADMISSION.en.md) · [ТЗ ядра](TECHNICAL_SPECIFICATION.md)

Принятые требования core 1.18, раздел 6.7. Реализация отсутствует.

## Описание расширения

package.json содержит авторские сведения:

| Поле | Условие | Назначение |
| --- | --- | --- |
| publisher, name | Обязательны | ID publisher.name |
| version | Обязательно | Версия расширения |
| displayName, description | Обязательны | Отображение пользователю |
| engines | Обязательно | Совместимость с API ядра |
| main | Есть исполняемая часть | Проверенная точка входа |
| contributes | Есть объявляемые возможности | Настройки, события, действия, редакторы |
| dependencies | Есть зависимости | Ограничения версий |
| permissions | Нужны полномочия | Явный запрос возможностей |

Отсутствие последних двух полей означает пустые наборы. contributes.configuration
ссылается на settings.schema.json при наличии настроек. Все ссылки проверяются
внутри комплекта. JSON не исполняется. Семантика версий/типов и набор допустимых
capabilities/permissions ещё требуют конкретизации; это не готовая JSON Schema.

## Вычисляемый manifest комплекта

Сборщик формирует список файлов, SHA256, размеры, платформу, конкретные версии
зависимостей и kernel ABI для kmod. Проверяется согласованность с package.json,
реальное содержимое и полнота. Необъявленные файлы не устанавливаются. Это не
manifest экспорта settings/template/backup. SHA256 не заменяет доверие источнику.

## Порядок допуска

1. Ограниченный разбор формата, проверка идентичности/совместимости и доверия.
2. Полный состав файлов и локальных зависимостей; неизвестные обязательные
   возможности/поля или несовместимость означают отказ.
3. Проверка путей, типов и владения: нельзя выйти через .., абсолютный путь,
   ссылки, специальные файлы или дубли назначения; чужие и пользовательские
   файлы не перезаписываются молча.
4. Расчёт пиков каждой ФС и RAM с резервом, ограничение размера/числа файлов
   и работы распаковки. Значения автора проверяются, ресурс проверяется повторно.
5. План изменений и полномочий для проверки перед применением.
6. Изолированная подготовка, затем активация проверенного комплекта с путём
   восстановления; подмена после проверки запрещена.

Первый формат устанавливается декларативно, без произвольных shell-hooks
расширения. Зависимые штатные IPK с hooks требуют отдельной политики доверия;
произвольный пакет нельзя объявить зависимостью для обхода запрета.

permissions — декларация, не sandbox. До реализации нужны механизмы контроля
и явные ограничения: нельзя обещать безопасность произвольного root-кода.
Проверка/подготовка не запускает звук, управление оборудованием или изменение
сети. Неизвестные обязательные полномочия отклоняются.
