# Проверка релизов и обновление расширений

[English](RELEASE_UPDATES.en.md)

26.10.2026. Требования, **без реализации**. Нормативный владелец — [ТЗ ядра](TECHNICAL_SPECIFICATION.md), 6.11, ревизия 1.35. Требования интерфейса «Школьника» — [ТЗ пакета](../packages/schoolbell/TECHNICAL_SPECIFICATION.md), 4.8, ревизия 1.55. Наличие IPK и GitHub Release не означает готовность автоматического обновлятора.

## Что видит пользователь

1. Ненавязчивое уведомление о проверенном совместимом обновлении; непроверенный выпуск обозначен отдельно.
2. «Настройки → Обновление»: версия, изменения, совместимость, место и состояние последней проверки. Отключаемая фоновая проверка и ручная кнопка; отсутствие Интернета не мешает устройству работать.
3. Администратор выбирает «Подготовить обновление»: проверка комплекта, зависимостей, места, копии и отката. Никакой установки при открытии страницы или нажатии проверки.
4. «Установить обновление» — отдельное подтверждение неизменившегося плана. Пакет предъявляет условия готовности. Для «Школьника» звонки выключены до и после операции.
5. После обрыва связи — просмотр результата той же операции. При незавершённой установке — понятный путь восстановления, без слепого повторного POST.

Экран пакета скрывает техническую сложность общего сервиса, но показывает причину отказа и требуемое действие. IPK/hooks не дублируются в каждом UI. Протокол вызовов сервиса и конкретная модель ACL ещё требуют согласования.

Идентичность package.json — будущий контракт, не новый установленный файл. Имена существующих IPK не меняются. GitHub tag/name не используются как версия приложения: общий релиз может содержать разные версии ядра и нескольких пакетов. Не все расширения обязаны иметь ту же грамматику версии, что schoolbell; их сравнение требует объявленного поддерживаемого профиля. opkg-зависимости сохраняют свою штатную грамматику. `all` не доказывает переносимость native/kmod.

Одна версия с изменёнными байтами не переиздаётся как прежняя: новый patch. Идентификатор исходного коммита и SHA связывают конкретную сборку, но подпись коммита не заменяет подпись поставляемых артефактов.

## Метаданные предложения

Будущий signed release manifest связывает идентичность/версию, release/source commit, поддерживаемый профиль платформы и API, зависимости и точные выбранные артефакты, размеры/SHA256, схему/миграции данных и ограничения отката. Сведения manifest сверяются с IPK control/Depends и содержимым, а не принимаются на веру. Формат/типы, exact-byte Ed25519 и логический API заданы в [SIGNED_RELEASES.md](SIGNED_RELEASES.md); системные механизмы открыты в core 9.2.31; существующий build manifest `format:1` пока **не является подписанным контрактом обновления**.

Выбор рассматривает релизы конкретного компонента и совместимость, не только `/releases/latest`. Нельзя объявлять «обновлений нет», если просмотр ограничен квотой и поиск не завершён. Профиль чтения определит ограниченные JSON/пагинацию, время и память до реализации. Не вводятся бесконечные запросы ради полноты.

## Зависимости, автономность, доверие

Рабочая база: OpenWrt 19.07.9 / ramips/mt76x8 / mipsel_24kc / musl / Lua 5.1. Точные firmware/kernel ABI берутся из проверяемого профиля, а не только из номера OpenWrt. Совместимые установленные зависимости сохраняются; комплект содержит недостающие выбранные зависимости и всё необходимое для восстановления без сети. Несовместимые firmware/kmod/libc не заменяются попутно. Обновление ядра — отдельное решение.

Доверенный ключ поступает вне скачанного релиза. SHA, HTTPS, GitHub asset digest и подпись Git-коммита не заменяют подпись release manifest. Неизвестный ключ/подпись/обязательная возможность, неверные пути/размеры/ABI или нехватка места закрывают допуск. Проверка не меняет часы для прохождения TLS; неверное время/CA показываются как причина недоступности.

Число фоновых попыток ограничено интервалом не менее 86400 с по монотонным часам; проверка не скачивает IPK сама. Дополнительные таймауты/backoff/ресурсные лимиты и поведение первого запуска ещё задаются перед реализацией. GET-кэш допускается; rate limits и Retry-After соблюдаются, ручная кнопка их не обходит. Открывать входящий доступ к устройству/webhook не требуется.

## Восстановление и границы

Подготовка держит резервную копию и совместимый предыдущий комплект. В интерфейсе доступна выгрузка копии вне устройства; способ доказать/подтвердить её сохранение — открытая деталь. Если код старой версии не читает новые данные, возврат предусматривает исходную копию, а не молчаливое удаление неизвестных полей.

opkg не становится транзакционной системой от наличия backup. Потеря питания после начала записи может потребовать внешнего восстановления. До доказанного окончания операции активация затронутого пакета запрещена. Автоустановка без человека, автоматический reboot, смена firmware/сети/NTP и выпуск релиза агентом вне области.

## Последовательность разработки

- Использовать SIGNED_RELEASES.md для изолированной модели; выбрать verifier/ключи, HTTPS, wire/ACL и системные бюджеты до подключения к сети.
- Изолированное обнаружение и уведомление: подменяемая сеть, offline/TLS/rate limit, разные компоненты/версии и изменённый релиз.
- UI «Школьника» для уведомления/проверки без установки; Pages моделирует состояния.
- Изолированный admission/подготовка/operation/recovery и fault tests.
- Авторизованное применение только после отдельной приёмки профиля и аппаратных испытаний.

TC-144–149 ядра и TC-146–149 schoolbell — **плановые**, не PASS. В этой ветке проверяется только согласованность документов.
