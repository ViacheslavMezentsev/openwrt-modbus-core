# Порядок совместной работы

[English](WORKFLOW.en.md) · [Разработка](DEVELOPMENT.md) · [CI](CI.md)

Эта памятка описывает повторяемый цикл владельца проекта и Codex: от выбора
небольшого этапа до подтверждения результата на устройстве. Правила репозитория
заданы в [AGENTS.md](../AGENTS.md); команды сборки — в DEVELOPMENT.

## Кто что делает

| Участник | Ответственность |
| --- | --- |
| Владелец | Выбирает следующий этап, принимает поведение и результат, разрешает воздействия на устройство; выполняет push, land, публикацию Pages, теги и релизы |
| Codex | Сверяет исходное состояние, готовит ветку, требования/код/тесты, документацию и подписанный коммит; проводит разрешённые проверки, готовит резервную копию и откат, сообщает факты и ограничения |

Новые PR в этом цикле не создаются. Разрешение на реализацию не означает
разрешения на установку, звук, включение автоматики или изменение часов.
Уже согласованные действия не требуют повторного разрешения в пределах того же
этапа. Изменившийся объём воздействия согласуется отдельно.

## 1. Выбор этапа и исходная точка

1. Прочитать AGENTS, README, TODO, Unreleased и документы затронутого компонента.
2. Проверить `git status`, текущую ветку, локальные коммиты и `origin/main`
   после `git fetch origin`. Сообщение «слил» проверяется по Git.
3. Не удалять и не прятать чужие изменения ради переключения. При расхождении
   выяснить происхождение изменений; не использовать принудительный сброс.
4. Согласовать небольшой проверяемый результат и границы: требования или
   реализация, только хост или устройство, допустимы ли звук и автозвонки.
5. Начать `codex/<задача>` от актуального чистого `main`. Подходящую незавершённую
   ветку продолжать, если это согласовано; один законченный этап — одна ветка.

Новое поведение сначала описывается в ТЗ владельца функции: ядро и пакеты ведут
отдельные требования. Неизвестное остаётся открытым вопросом. Ветка только с
требованиями не выдаётся за реализацию и не меняет установленный пакет.

## 2. Реализация и проверки на хосте

Сначала воспроизвести проблему или определить критерии нового поведения, затем
изменить код и добавить содержательные проверки. Ошибки, границы, конкуренция,
потеря ответа и сохранность пользовательских данных проверяются там, где это
затронуто изменением. Исправление причины важнее повторных ручных попыток.

| Область изменения | Проверки |
| --- | --- |
| Только документация | `make check-docs`, проверка diff и соответствия описания фактам |
| Runtime, пакет, общие механизмы | Профильные регрессии и `make all` с нужными зависимостями, включая Lua 5.1 |
| Интерфейс «Школьника» | UI-регрессии, `make check-site`, осмотр отображения; синхронизация общих исходников Pages |
| Прошивка | Профильные тесты и `sh scripts/build-bluepill.sh`; прошивка устройства отдельно согласуется |

`skipped` не означает PASS. Отчёт различает проверку модели, реального кода на
хосте, изолированный опыт на устройстве и рабочую установку. После правок,
вызванных тестом, повторяются затронутые проверки. CI не заменяет стенд.

Обновляются TODO, Unreleased соответствующего компонента, затронутые требования
и публичные документы RU/EN. Версия пакета отличает устанавливаемые сборки;
правка только документации не требует новой версии IPK. Для «Школьника» принят
major.minor.patch; небольшие изменения пакета повышают patch.

## 3. Подписанный коммит и передача владельцу

- Просмотреть diff и `git diff --check`. Добавлять конкретные файлы, а не всю
  папку docs. Исследования, резервные копии, аппаратные логи и скачанные сборки
  остаются вне Git; `git add -f` для них не применяется.
- Сделать английский Conventional Commit с подписью настроенного ключа.
  В нашем окружении коммит делает Windows Git через UNC-путь к репозиторию WSL.
  Ключ не копируется в WSL; подпись не отключается при ошибке.
- Проверить подпись и чистоту дерева также через WSL Git: права файлов и
  окончания строк не должны создавать случайные изменения.
- Сообщить ветку, SHA, изменения, выполненные проверки, пропуски, ограничения
  и следующий шаг. Подготовить команды владельцу с точным именем ветки.

Пример (заменить имя на ветку завершённого этапа):

```sh
git push -u origin codex/example-stage
gh run list --branch codex/example-stage
gh run watch <RUN_ID> --exit-status
```

Перед слиянием сверить `headSha` запуска с отправленным SHA и успешный итоговый
`ci-gate`. Зелёный запуск предыдущего коммита или отдельного задания недостаточен.
Только после этого владелец выполняет:

```sh
git land codex/example-stage
```

`git land` — локальный helper, а не встроенная команда Git; он сам не проверяет
CI. Его действия и ручной вариант описаны в DEVELOPMENT. Если main изменился
и fast-forward невозможен, интеграция выполняется отдельно; новый HEAD снова
проверяется и проходит CI. Force-push и обход проверок не применяются.

## 4. Установка и проверка на устройстве

Обычный порядок: хост → подписанный коммит → push/CI/land владельцем → отдельное
разрешение на установку → резервная копия → установка → проверка.
По явной договорённости стендовая проверка возможна **до push** в текущей ветке.
Тогда фиксируются точный SHA и состав сборки, ветка не отправляется до принятия
результата; исправления повторно тестируются и коммитятся перед передачей.

Перед установкой Codex:

1. Сверяет установленную и предлагаемую версии/состав, свободное место и
   исходное состояние автоматики. Не полагается только на номер версии.
2. Сохраняет локально свежую резервную копию настроек, планов, пользовательских
   мелодий и нужных метаданных; проверяет читаемость и состав копии.
3. Сохраняет подходящий предыдущий IPK/зависимости, контрольные суммы и команды
   отката. Подготовленный откат и реально проверенный откат — разные результаты.
4. Записывает цель, условия, допустимые действия и ожидаемый итог опыта.

Доступ идёт через WSL Ubuntu-20.04, SSH `openwrt`. Сборка выполняется на хосте;
компиляторы на устройство не ставятся. После установки проверяются состав,
версии, службы, сохранность данных и оговорённые системные настройки.

Автозвонки, звук, перезагрузка, отключение питания/USB, сеть, firmware и часы/NTP
не меняются автоматически ради проверки. При разрешённом тестовом включении
после теста возвращается согласованное состояние, обычно автозвонки выключены.
Serial нельзя открывать параллельно ядру. Временные IPK и собственный ненужный
кэш удаляются после проверки, без удаления пользовательских данных.

## 5. Проверка интерфейса с владельцем

Codex сначала выполняет доступные проверки самостоятельно, затем даёт короткую
последовательность действий в интерфейсе. Если шаги непонятны — по одному шагу,
с конкретным ожидаемым результатом. Ctrl+F5 предлагается после предупреждения
о несохранённых правках; нельзя терять их ради обновления страницы.

Ответ владельца подтверждает именно наблюдённое поведение: вид кнопки, сохранение
плана, слышимый звук. Он не заменяет проверку состояния на устройстве. При ошибке
сохраняются исходные сообщения и факты; не предлагают повторять изменяющую
операцию вслепую, пока неизвестен результат предыдущей.

Для Pages синхронизируются исходники, проходят сборка и локальный осмотр. Публикацию
выполняет владелец. «Исходники синхронизированы» и «публичная страница обновлена» —
разные статусы; демо не считается проверкой оборудования.

## 6. Завершение и следующий цикл

Аппаратный отчёт хранится локально в `docs/research/NN-name/`, данные опыта —
в `tests/manual/NN-name/`; локальный HISTORY пополняется сверху. Сохраняются и
исходные FAIL/ERROR. В публичные документы переносятся принятые выводы без
реальных идентификаторов и ссылок на отсутствующие локальные отчёты.

В итоговом сообщении указать:

- что реализовано и что подтвердил владелец;
- что проверено на хосте/устройстве и что ещё не проверялось;
- установленную версию, состояние автозвонков и сохранность данных;
- ветку/SHA и нужные команды либо факт, что push пока отложен;
- следующий небольшой этап из актуализированного TODO.

После «готово, слил» снова сверить Git и начать следующий цикл. Короткая успешная
проверка не означает приёмку автономной эксплуатации: для неё используется
отдельная [программа приёмки «Школьника»](packages/schoolbell/ACCEPTANCE.md).
