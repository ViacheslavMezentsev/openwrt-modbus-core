### 1.1. Соглашения

1.1.1. Номера требований и TC-NN локальны этому документу, не переиспользуются.
Ссылка вне документа включает имя пакета. ДОЛЖЕН означает обязательство после
утверждения; `[R]` — восстановлено по коду, `[N]` — новое, `[U]` — уточнение.
разделы 3–5 — нормативные; наличие тест-кейса не означает PASS.

сохраняет номера. Прототипы и аппаратные логи остаются локальными.

## 2. Общее описание

### 2.1. Границы и совместимость

2.1.1. Demo читает журнал ядра и показывает диагностику. Исходники `pkg-demo/`,
локальные тесты `scripts/test_demo.lua`. Serial, общий scheduler и маршрутизация
подписок не принадлежат demo. Исторические аппаратные результаты описаны в
[VALIDATION](../../VALIDATION.md); новый код 98ad0ea на роутере ещё не проверен.

2.1.2. Базовый контракт потребителя: ТЗ ядра 1.5, пункты 4.4.1, 4.4.6, 4.4.7,
6.1.2, 6.1.4–6.1.7; реализация ядра из ee4dabe, без гарантии будущей совместимости.
Зависимость opkg пока `modbus-rtu-core` без версии; отдельного API version нет.
Контракт — два JSONL-сегмента в /tmp/modbus с seq/kind/ts. Новые ограничения
совместимости потребуют проверки, а не вывода из номера релиза 0.4.0.

## 3. Функциональные требования

### 3.1. Потребление событий

3.1.1. При стандартном runtime-каталоге demo ДОЛЖЕН читать журнал ядра и обновлять `demo-status.json` с количеством обработанных событий и последним событием без открытия serial-порта. Обработка обнаруживаемых разрывов определена в п. 3.1.2–3.1.5; exactly-once и восстановление вытесненных событий не гарантируются. `[U]`

3.1.2. При отсутствующем или нулевом сохранённом курсоре demo ДОЛЖЕН начать с конца первого подтверждённого снимка; его старые записи не учитываются. Пустой первый снимок устанавливает курсор 0 для следующих событий. `[U]`

3.1.3. При непустом подтверждённом снимке с максимальным seq меньше курсора demo ДОЛЖЕН обработать доступную последовательность с начала и отметить сброс; пустой снимок курсор не сбрасывает. Сброс, уже догнавший прежний курсор, по одному seq не определяется. `[N]`

3.1.4. Demo ДОЛЖЕН учитывать каждый целый положительный seq не более одного раза в подтверждённом снимке, сортировать записи и диагностировать отсутствующие номера от курсора до принятого максимума (после обнаруженного reset — от 0). При повторе seq сохраняется первая прочитанная запись. Статус содержит `gap_events`/`sequence_reset` за цикл и накопительные `missed_events`/`sequence_resets` за запуск demo; это наблюдаемые пропуски, не точная оценка всех потерь между поколениями. `[N]`

3.1.5. Demo ДОЛЖЕН сравнивать содержимое двух последовательных чтений обоих сегментов, выполняя не более трёх попыток за цикл. При несовпадении всех снимков или ошибке чтения курсор и счётчик обработанных событий сохраняются, статус получает `read_error`, описание `read_error` и накопительный `read_errors`; следующая попытка — в следующем цикле. Отсутствие файла допустимо и отличается от пустого содержимого. Обрабатываются только завершённые LF записи. Сравнение не является транзакционным снимком и не гарантирует доставку при непрерывной ротации; persistence-ошибки остаются в вопросе 8.2.2. `[N]`

## 6. Верификация

A — анализ, I — инспекция, T — локальный тест, D — оборудование.

| TC | Сценарий | Ожидание / статус |
| --- | --- | --- |
| TC-01 | Получение событий без serial | Счётчик/последнее событие; scripts/test_demo.lua и интеграционные scripts/test-core-demo-router.sh, scripts/test-bluepill-router.sh |
| TC-02 | Старт, пустота, reset, пропуски и дубли | scripts/test_demo.lua; прежний тест ядра №37 |
| TC-03 | Ротация, ограничение повторов, отказ чтения, неполная строка | Курсор сохранён на ошибке; scripts/test_demo.lua; прежний тест ядра №38 |

и синтетический JSON-кодек. Реальная luci.jsonc и ресурсы платы им не проверяются.
Новый аппаратный PASS не выводится из старого протокола.

## 8. Допущения и открытые вопросы

### 8.1. Допущения

8.1.1. Файлы runtime доступны, один штатный писатель журнала. Exactly-once,
обнаружение reset, догнавшего курсор, и восстановление вытесненной истории
не гарантируются. Пауза цикла 2 с — не дедлайн. RAM/CPU не нормированы.
