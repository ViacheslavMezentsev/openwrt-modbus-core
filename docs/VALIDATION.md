## Штатные регрессии

`make all` с Lua 5.1 запускает `scripts/test_events.lua` и
`scripts/test_topics.lua`: новый экземпляр писателя продолжает сохранённый seq,
пустой runtime начинает с 1, CLI после пустого интервала обнаруживает меньший
seq и выдаёт записи новой последовательности без повторов. Тесты работают в
изолированном временном каталоге и не перезагружают устройства.
Это не тест атомарности файлов при потере питания и не тест всех разрывов demo.

## Обновление и откат

Перед установкой сохранить фактически установленные файлы ядра, UCI,
пользовательские handlers/triggers, conffiles, пакетные хуки и метаданные opkg,
автозапуск. Проверить распаковку и хеши копии; откатный IPK сверить с исходными
файлами. Глобальную базу opkg и сетевую конфигурацию не заменять при точечном откате.

Различать сборки по версии с ревизией и SHA-256 payload/IPK. Одного `0.4.0`
недостаточно. Собрать только ядро через `make build-core VERSION=<build-version>`;
не использовать установщик обоих пакетов для обновления одного ядра.

Список conffiles не является безусловной защитой. Если откатный пакет собран
с текущей пользовательской UCI как пакетным default, при следующем обновлении
opkg может считать её неизменённой и заменить новым default. После установки
сверить сохранённые настройки; при замене остановить ядро, восстановить рабочую
копию, сверить хеши и запустить ядро. Затем проверить свежие core/demo, топики,
serial owner и убрать только временные файлы этой установки. Резервные копии
оставить локально. Команда отката — аварийный путь, не завершающий шаг обновления.

## Правила наблюдения

- `meta.started_at` загружается из кэша; новый процесс определять по PID и
  `/proc/PID/stat` starttime, новую загрузку — по boot ID.
- Снимки времени и файлов не атомарны. Фиксировать начало/конец чтения;
  обновление между чтениями может дать кажущийся age=-1 с. Сохранять исходную
  отметку и разбирать её, не маскировать реальные скачки часов.
- Читать оба сегмента журнала, проверять seq и отличать пропуск наблюдателя
  от отсутствия события. После reboot seq не является глобальным ID.
- System topic age относится к публикации изменения, не к каждому USB-опросу.
- Каждый новый reboot, USB disconnect/reset и длительный прогон согласуется
  отдельно. Только ядро владеет serial. Ограничения ТЗ остаются открытыми.

## Уменьшение лимита журнала

Согласованная политика (ТЗ 1.3): настройка лимита не изменяет файлы сразу.
Большой архив сохраняется до ротации активного сегмента. Если активный сегмент
уже превышает лимит, следующая допустимая запись удаляет его и старый архив
целиком; seq продолжается. Это допустимая потеря истории, без перепаковки строк.
Отказ новой oversized-записи не выполняет очистку и сохраняет файлы.
TC-35/36 проверяют эти случаи локально. Ошибки ФС и память сериализации
этими тестами не покрыты; немедленное соблюдение нового лимита обоими старыми
сегментами не гарантируется.
